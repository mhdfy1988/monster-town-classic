# 青芽纪行第一章

## 目标与当前范围

目标是可完整游玩的口袋怪兽 RPG 第一章。玩家从青芽镇出发，领取伙伴并完成捕捉教学；通过巡林员考核后回研究所接受博士的森林调查委托；在风铃森林调查测量员、苔光与白砾留下的工程线索，再进入回声洞穴依次激活三块回声石，关闭过热设备并安抚熔岩巨龟；最终返镇完成调查结算并取得河湾镇通行证。

这是本地浏览器可玩版本，没有宣称完成第二、三章、联机、手机版触控、桌面打包或公开发行。持续性异常状态、更多洞穴互动与通用对象/事件编辑仍留在后续计划；直线三阶进化、等级招式、战斗内增减益、第一章 NPC 任务链和两条支线已经实现。

## 技术与入口

- 仓库：当前 `monster-town-classic` 项目根目录
- 游戏：`http://127.0.0.1:4190/`
- 启动：`npm.cmd run dev -- --host 127.0.0.1 --port 4190 --strictPort`
- 检查：`npm.cmd test`、`npm.cmd run build`
- Phaser 3.90.0、TypeScript、Vite。沿用已有依赖，没有为新玩法额外引入引擎。

`src/main.ts` 只启动当前游戏。`src/rpg/model.ts` 定义伙伴、伤害、经验和存档规则；`battleProgress.ts` 把全队经验、升级、招式变化与进化整理为可测试的战后成长事件；世界模块提供道路、长草、场景物件和独立碰撞区域；`RpgScene.ts` 连接 Phaser 场景、回合流程、输入与界面；`modalFrame.css` 管理普通弹窗与战后结算的像素框架。

当前资源、运行地图、交互、移动、洞穴机关、战斗会话、战斗流程、存档、HUD 与专属界面已经拆入对应模块；`RpgScene` 保留 Phaser 生命周期和用例编排。当前 8 个种族、24 个形态仍无需提前引入大型框架。

## 状态与数据

第1轮：开始新旅程 → 博士选择伙伴 → 写入队伍与图鉴。

第2轮：长草步行 → 遭遇野生伙伴 → 玩家指令 → 对手反击 → 胜利后计算全队成长 → 逐位展示经验、升级、招式与进化 → 保存并回到探索。捕捉或离开不发放胜利经验，直接记录结果并回到探索。

第3轮：图鉴拥有两种伙伴 → 可挑战巡林员 → 获胜写入徽章、金币、经验与 `ranger-pass` → 返回研究所接受博士的正式调查委托，写入 `forest-investigation` 并开放北门。

第4轮：从青芽镇北门进入独立风铃森林 → 与测量员交谈并调查三处苔光线索 → 在白砾处确认引路塔工程背景 → 可向林川提交“迷路的测量员”，向小夏提交“暗淡的苔光” → 清理北侧倒木与碎石，写入 `forest-route-cleared` 并进入回声洞穴。

第5轮：洞口确认这里原本是旧引路塔的设备试验场 → 沿环形矿轨依次激活低音、中音、高音回声石；错误音序显式重置，完整音序解除三重声锁 → 关闭过热设备。

第6轮：迎战不可捕捉、不可逃跑的熔岩巨龟 → 全队获得经验并播放成长结算 → 写入首领击败和 `magma-tortoise-calmed` → 原路返回青芽镇，分别听取林川和博士的结算 → 由镇长写入 `chapter-1-complete`、`riverbend-pass` 并推进到第二章入口占位。

药水和换人消耗回合。训练家伙伴不可捕捉。血量为零自动换到存活伙伴；全队失去战斗力回驿站免费恢复。随行队伍上限为五位，超出的捕捉伙伴进入收容箱，可与队伍交换。驿站可将不足三个的捕捉球补足，避免无资源死局。

胜利经验以结算开始时的随行顺序计算：当前首发获得基础经验的 100%，其他随行伙伴获得 60%，包括本场没有出战的成员。成长事件先完成真实等级与形态数据变更，再交给结算界面逐项展示；界面不自行猜测是否升级、领悟或进化。由等级自动开放的招式立即可用，进化导致的属性招式更名显示为“招式进化”。

存档格式在 `model.ts` 中定义，浏览器存储键仍为 `pocket-grove-rpg-v1`，当前数据格式版本为 v3。v1、v2 数据会逐版显式迁移到稳定地图 ID、剧情状态与支线任务结构；关键操作及每10步自动保存，也有手动保存。加载时检查版本、地图、合法落点、伙伴索引、等级、血量、库存、剧情与支线结构；损坏或未知版本存档明确提示，不静默回退。战斗中刷新回到最近的探索存档，不恢复到回合中途。

早期地图编辑器和浏览器地图库已经移除；当前地图是项目源码中的正式游戏内容，不再同时维护一套无关的用户地图工作流。

## 后续计划

适配第二次修正：用户截图证实旧版整页高度溢出，先前仅检查按钮的验证不充分。现改为整页网格分配剩余高度，Phaser RESIZE同步画布实际尺寸，并清除旧`#game`边框与固定比例影响。1920×934、1536×747、1280×622、960×467、1366×768五组可用窗口验证：全部战斗按钮和底栏可见，画布CSS与逻辑尺寸差均为0。后三组也覆盖放大浏览器后可用CSS空间缩小的情况，但未宣称自动操作真实浏览器缩放菜单。矮窗口三列指令，独立调整对手与状态面板避免重叠。

本轮追加体验优化：商店由通用对话按钮改为商品列表，显示库存、组价和成交反馈；建筑以底部锚点生成独立地面接触阴影与右下投影，不修改原图、不改变碰撞。行走采样验证帧按1、0、1、2连续切换，松键回到1号站立帧。步行每格180ms。

适配验证覆盖1920×1080、1366×768、800×600、390×844：商店面板、购买及离开按钮未越界，无横向页面溢出；1366、800、390宽度的战斗按钮均完整可见。小屏适配不等于已实现触屏移动，当前仍以键盘和鼠标为主。

经验：画布尺寸与DOM界面必须使用一致的宽高比约束；不要只截短画布父容器高度。行走中间帧与站立帧要分开，撞墙时也应回到当前方向的站立帧。

方向映射修正：`walk-adventurer.png` 放大核对后确认四行依次为下、左、右、上，起始帧为0、3、6、9，站立帧为1、4、7、10。此前错误使用下、上、左、右，导致三个方向错位。此前步态采样只验证了帧在变化，不证明朝向正确；今后必须同时核对原图朝向、位移方向和实际使用帧。

1. 后续地图继续使用源码内的静态地图文档与独立碰撞区域，并通过运行地图注册表接入入口、NPC 和剧情事件。
2. 按这套美术扩展第二条路线与第二个城镇，增加训练家阵容、探索奖励和任务分支。
3. 扩展持续性异常状态、招式替换和属性平衡，再调成长与捕捉节奏。
4. 补控制器/触屏、音频资源和桌面封装，最后再考虑公开发行。

## 本轮经验

此前逐块生成再缩放的方式无法稳定保证连接、比例与完整场景，成本很高。本轮采用成熟项目的整套图集、保留授权，再用实际游戏验证切片和连接，能够直接支撑玩法。首轮映射曾把边缘样本误作长草和水心；实机截图发现后改为对应动画/水面图集，并合并道路交叉口，未继续靠生成新素材掩盖映射问题。

长期规则：先选能拼成完整地图的成熟素材体系，核对样例和精确图集坐标，再做原创补充；游戏的验收单位是一段可玩的旅程。
